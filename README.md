# TerminalAI — Повнофункціональне AI-розширення для Windows Terminal та PowerShell

[![PowerShell](https://img.shields.io/badge/PowerShell-7%2B%20%7C%205.1-blue?logo=powershell&logoColor=white)](https://github.com/PowerShell/PowerShell)
[![Windows Terminal](https://img.shields.io/badge/Windows%20Terminal-Fragment%20Extension-black?logo=windows-terminal&logoColor=white)](https://github.com/microsoft/terminal)
[![Ollama](https://img.shields.io/badge/Ollama-100%25%20Local-purple?logo=ollama&logoColor=white)](https://ollama.com)
[![Privacy](https://img.shields.io/badge/Privacy-Offline%20%26%20Zero--Cloud-green)](https://ollama.com)

**TerminalAI** — це потужне, повністю локальне розширення для **Windows Terminal** та консолі **PowerShell**, яке інтегрує сучасні великі мовні моделі через **Ollama** (`qwen2.5-coder`, `granite4.2`, `qwen3.5` тощо) безпосередньо у ваш командний рядок.

Усі обчислення виконуються на 100% на вашому обладнанні (GPU/CPU) — **жодні дані, шляхи до файлів чи команди не надсилаються в хмару**, відсутні платні підписки, а швидкість відповіді досягає часток секунди.

## 🌟 Ключові переваги

- **🔒 100% Конфіденційність:** Працює офлайн без зовнішніх API-ключів та витоку корпоративних даних.
- **⚡ Інлайн-автодоповнення з живим таймером:** Натисніть **`F2`** або **`Ctrl+G`** — рядок із коментарем миттєво перетворюється на анімований спінер із відліком секунд (`# [AI ⠋ 2s] ...`), а потім на готову команду.
- **🌐 Повна підтримка будь-яких мовних розкладок:** Обробники клавіш оптимізовані під українську та англійську розкладки (`Ctrl+G` / `Ctrl+п`, `Ctrl+Alt+A`).
- **🔤 Бездоганний UTF-8:** Більше жодних спотворень кирилиці або знаків запитання `??????` у консолі.
- **🎯 Детермінізм та стабільність:** Уніфікований системний промпт із `Temperature = 0.0` гарантує надійні конвеєри (`Get-Process`, `Get-ChildItem` тощо) без використання крихких системних лічильників.
- **🧩 Офіційне розширення Windows Terminal:** Інтеграція через JSON Fragment Extension — плагін офіційно з'являється у вкладці **Settings ➔ Extensions**.

## 📦 Швидкий старт (Встановлення за 1 клік)

1. Відкрийте термінал у каталозі проєкту:
   ```powershell
   pwsh -ExecutionPolicy Bypass -File .\Install-TerminalAi.ps1
   ```
2. Інсталятор виконає все автоматично:
   - Перевірить з'єднання з локальною Ollama (`http://localhost:11434`) та виявить активні моделі.
   - Зареєструє модуль `TerminalAI` у системному каталозі `$env:PSModulePath`.
   - Налаштує гарантовану підтримку UTF-8 та автоімпорт у `$PROFILE`.
   - Зареєструє **Fragment Extension** у каталозі Windows Terminal (`%LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\TerminalAI`).
3. Перезавантажте сесію терміналу або виконайте:
   ```powershell
   . $PROFILE
   ```

## 🛠️ Огляд функціоналу

### 1. Інлайн-генерація за гарячими клавішами (`F2` / `Ctrl+G`)

Найшвидший спосіб отримати команду прямо в рядку введення без зайвих кліків:

1. Напишіть у консолі короткий опис завдання з префіксом `#`:
   ```powershell
   # показати 5 процесів з найбільшим споживанням процесора
   ```
2. Натисніть **`F2`** (або **`Ctrl+G`** / **`Ctrl+Alt+A`**).
3. Ви побачите анімований живий індикатор виконання:
   ```powershell
   # [AI ⠋ 2s] показати 5 процесів з найбільшим...
   ```
4. Рядок автоматично заміниться на готовий до виконання код:
   ```powershell
   Get-Process | Sort-Object -Property TotalProcessorTime -Descending | Select-Object -First 5 Name, Id, TotalProcessorTime
   ```
5. За потреби відредагуйте параметри або натисніть **Enter** для запуску!

> [!TIP]
> Якщо натиснути `F2` або `Ctrl+G` на порожньому рядку, плагін автоматично вставить шаблон `# [AI Запит]: `, запрошуючи до введення.

### 2. Інтерактивна команда `ai` / `??`

Для складних запитів, попереднього перегляду, копіювання чи отримання пояснень:

```powershell
ai знайти всі файли більше 100MB змінені за останній тиждень
```
*(або скорочений синтаксис: `?? знайти всі файли...`)*

#### Результат у консолі:
```text
  ✦ Звертаюсь до Ollama (qwen2.5-coder:7b)...

    ✦ AI Команда • qwen2.5-coder:7b
    ╭────────────────────────────────────────────────────────────────────────────╮
    │                                                                            │
    │  Get-ChildItem -Recurse -File |                                            │
    │    Where-Object { $_.Length -gt 100MB -and $_.LastWriteTime -gt (Get-Date).AddDays(-7) }│
    │                                                                            │
    ╰────────────────────────────────────────────────────────────────────────────╯

    [Enter] Виконати          [C] Скопіювати        [I] Вставити в рядок
    [X]     Пояснити код      [A] Текстова відповідь [Esc] Скасувати
```

#### Керування в меню:
- **`Enter`** — миттєво виконати згенерований код.
- **`C`** — скопіювати команду у буфер обміну Windows.
- **`I`** — чисто вставити команду у наступний рядок запрошення `PS>` для редагування (без засмічення старого буфера).
- **`X`** — згенерувати покрокове технічне пояснення команди українською мовою.
- **`A`** — перейти в режим текстової консультації (якщо ви задали інформаційне питання, а не прохання написати код).
- **`Esc`** — відхилити та очистити меню.

#### Прапорці швидкого виконання:
- `-x` або `-Execute` — виконати команду одразу без виклику меню:
  ```powershell
  ai перезапустити службу Spooler -x
  ```
- `-c` або `-Copy` — згенерувати та відразу скопіювати у буфер обміну:
  ```powershell
  ai вивести IP адресу шлюзу -c
  ```
- `ai` *(без аргументів)* — викликає стильну картку швидкої довідки з прикладами.

### 3. Автоматичне виправлення помилок (`ai-fix`)

Якщо попередня команда в терміналі впала з помилкою:

```powershell
Get-ChildItem -Path C:\Logs -Filter *.log -Recurse -ExcludeOld
# Помилка: A parameter cannot be found that matches parameter name 'ExcludeOld'.

ai-fix
```

**TerminalAI** автоматично зчитає текст останньої команди з історії та системний об'єкт винятку `$Error[0]`, пояснить причину помилки зрозумілою мовою та запропонує виправлений варіант із меню дій.

### 4. Генератор виробничих скриптів (`ai-script`)

Для генерації багаторядкових сценаріїв автоматизації з обробкою винятків, логуванням та типізованими параметрами:

```powershell
ai-script "Архівація папки C:\Data у ZIP з датою в назві та видалення вихідних файлів"
```

#### Додаткові параметри:
- `-OutputPath <шлях>` — автоматично зберегти результат у файл `.ps1`:
  ```powershell
  ai-script "Моніторинг вільного місця на дисках" -OutputPath ./Check-Disks.ps1 -Edit
  ```
- `-Edit` — після генерації відразу відкрити збережений файл у VS Code (або Блокноті).

### 5. Інтерактивний діалоговий агент (`ai-chat` / `ai-assistant`)

Для складних консультацій, покрокового проектування скриптів або безперервного діалогу запустіть повноцінний REPL-сеанс помічника:

```powershell
ai-chat
# або з вибором конкретної моделі:
ai-chat -Model qwen2.5-coder:7b
```

#### Ключові можливості агента:
- ⌨️ **Tab-автодоповнення слеш-команд:** Наберіть `/` і натисніть **`Tab`** для швидкого перебору команд (`/help`, `/models`, `/model`, `/lang`, `/copy`, `/save`, `/clear`, `/exit`).
- 🤖 **Tab-автодоповнення моделей Ollama:** Наберіть `/model ` і натисніть **`Tab`** — помічник автоматично підтягне локально встановлені моделі Ollama (`/model qwen2.5-coder:7b`, `/model granite4.2:8b` тощо).
- 🌐 **Миттєве перемикання мови (`/lang`):** Введіть `/lang uk` або `/lang en` (з підтримкою Tab), щоб змінити мову інтерфейсу, системних інструкцій та відповідей.
- 📋 **Копіювання та збереження коду:** Після генерації блоку коду введіть `/copy`, щоб скопіювати код у буфер обміну, або `/save deploy.ps1`, щоб зберегти у файл.
- 📖 **Вбудована довідка (`/help` / `/?`):** Виводить структуровану шпаргалку з переліком усіх команд та гарячих клавіш.

```text
    ✦ Terminal AI Assistant • Швидка довідка
    ╭──────────────────────────────────────────────────────────────────╮
    │                                                                  │
    │   /help          - Показати детальну довідку з командами         │
    │   /models        - Переглянути встановлені моделі Ollama         │
    │   /model <name>  - Змінити активну модель                        │
    │   /lang <uk|en>  - Змінити мову інтерфейсу (uk / en)             │
    │   /copy          - Скопіювати останній згенерований блок коду    │
    │   /save [file]   - Зберегти останній код у файл .ps1             │
    │   /clear         - Очистити екран                                │
    │   /exit          - Вийти з асистента                             │
    │                                                                  │
    ╰──────────────────────────────────────────────────────────────────╯
```

### 6. Відокремлення ролей: `ai` vs `ai-chat` (Коли що обирати)

Розширення розділяє сценарії взаємодії на два чітких напрямки:

| Критерій | `ai` / `??` / `F2` (Інлайн-генератор) | `ai-chat` / `TerminalAiAssistant.ps1` (Агент-помічник) |
| :--- | :--- | :--- |
| **Основне призначення** | Одноразова генерація конкретної PowerShell-команди для негайного виконання | Багатокроковий діалог, аналіз архітектури, проектування та навчання |
| **Режим роботи** | Одинарний запит без збереження історії (Single-shot) | Інтерактивна консольна REPL-сесія з контекстом |
| **Температура моделі** | `Temperature = 0.0` (максимальний детермінізм і точність синтаксису) | `Temperature = 0.3` (гнучкість, розгорнуті пояснення, креативність) |
| **Місце в інтерфейсі** | Безпосередньо в активному рядку вводу або як швидка картка | В окремому вікні або бічній спліт-панелі Windows Terminal (Split Pane) |
| **Взаємодія** | Меню дій: `[Enter]` запустити, `[I]` вставити в рядок, `[C]` скопіювати | Слеш-команди: `/help`, `/copy`, `/save`, `/model`, `/lang` з Tab-доповненням |

### 7. Інтеграція у Windows Terminal (Extensions & Split-Pane)

Завдяки нативному фрагменту `terminalai.json`, плагін інтегрується безпосередньо в інтерфейс Windows Terminal:

1. **Вкладка Extensions:** Перейдіть у **Settings ➔ Extensions** у Windows Terminal — ви побачите активне розширення **TerminalAI**.
2. **Палітра команд (`Ctrl+Shift+P`):**
   - Натисніть `Ctrl+Shift+P` та введіть `AI:`:
     - `AI: Запитати Ollama (ai)`
     - `AI: Виправити останню помилку (ai-fix)`
     - `AI: Згенерувати сценарій (ai-script)`
     - `AI: Відкрити асистента у спліт-панелі`
3. **Бічна панель асистента (Split-Pane):**
   Відкриває вертикальну панель (40% ширини) з повноцінним інтерактивним чат-ботом поруч із вашою робочою консоллю!

## ⚙️ Керування конфігурацією, шрифтами та мовою

Файл конфігурації зберігається у: `~/.terminal-ai/config.json`.

### 1. Перегляд поточної інформації про систему:
```powershell
ai status
# або: ai which model / ai info
```
Виводить стильну картку з активною моделлю, активним шрифтом Windows Terminal, URL-адресою Ollama, гарячою клавішею та поточною мовою.

### 2. Керування шрифтами Windows Terminal:
TerminalAI вміє автоматично зчитувати налаштування `settings.json` вашого Windows Terminal, фільтрувати моноширинні шрифти програмування та змінювати їх на льоту:
```powershell
# Переглянути доступні моноширинні кодингові шрифти:
ai fonts
# або: Show-TerminalAiFonts

# Змінити шрифт терміналу (застосовується миттєво без перезапуску):
ai font "Cascadia Code"
ai font "JetBrainsMonoNL Nerd Font Mono"

# Змінити шрифт разом із бажаним кеглем (розміром):
Set-TerminalAiFont -Font "Cascadia Code" -Size 13
```

### 3. Перемикання мови інтерфейсу (Українська / English):
Усі картки, меню дій (`[Enter]`, `[C]`, `[I]`, `[X]`), швидка довідка та системні пояснення повністю білінгвальні:
```powershell
# Переглянути поточну мову:
ai lang

# Змінити мову:
ai lang en
ai lang uk

# Встановити мову як ПОСТІЙНУ (за замовчуванням зберігається у config.json + $env:TERMINAL_AI_LANG):
ai lang permanent uk
ai lang permanent en

# Або через прямі командлети / аліаси:
ai-lang-permanent uk
ai-lang-default en
Set-TerminalAiLanguage -Language uk -Permanent
Set-TerminalAiDefaultLanguage uk

# Всередині діалогового агента ai-chat:
/lang permanent uk
/lang permanent en
```

> [!TIP]
> Команда з параметром `permanent` фіксує мову одразу на двох рівнях: у файлі конфігурації `~/.terminal-ai/config.json` та в системній змінній середовища користувача Windows (`$env:TERMINAL_AI_LANG`), тому обрана мова зберігається між перезавантаженнями та діє в усіх терміналах.

### 4. Перегляд та перемикання моделей Ollama:
```powershell
# Список моделей у локальній Ollama:
ai models
# або: Show-TerminalAiModels

# Змінити активну модель:
ai model qwen2.5-coder:7b
# або: Set-TerminalAiConfig -Model "qwen2.5-coder:7b"
```

### 5. Перегляд повної конфігурації:
```powershell
ai config
# або: Get-TerminalAiConfig
```

## ⚡ Як прискорити роботу моделей (Рекомендації)

Якщо генерація команди займає більше 2–3 секунд, скористайтеся цими перевіреними порадами:

### 1. Використовуйте спеціалізовані моделі коду замість загальних Reasoning-моделей
| Модель | Розмір VRAM | Швидкість на GPU | Особливості |
| :--- | :---: | :---: | :--- |
| **`qwen2.5-coder:7b`** *(Рекомендовано)* | ~4.7 GB | **1–2 секунди** | Ідеальний баланс знань PowerShell та швидкості. Не генерує зайвих думок. |
| **`qwen2.5-coder:3b`** *(Ультрашвидка)* | ~2.2 GB | **< 1 секунди** | Підходить для будь-яких ноутбуків і слабких GPU. |
| **`granite4.2:8b`** | ~5.3 GB | 10–18 секунд | Модель міркувань — витрачає час на внутрішній монолог перед генерацією коду. |

Встановіть рекомендовану модель:
```bash
ollama pull qwen2.5-coder:7b
ai model qwen2.5-coder:7b
```

### 2. Запобігання «холодному старту» (Keep-Alive)
За замовчуванням Ollama вивантажує модель з VRAM через 5 хвилин бездіяльності. Наступне звернення вимагає 3–5 секунд на повторне зчитування ваг із SSD.
- У **TerminalAI** вже вбудовано прапорець `keep_alive = "1h"`.
- Для постійного утримання моделей у пам'яті GPU встановіть системну змінну:
  ```powershell
  [Environment]::SetEnvironmentVariable("OLLAMA_KEEP_ALIVE", "-1", "User")
  ```

## 🔬 Архітектура: Робота з Ollama через HTTP vs CLI vs In-Process

Часте інженерне запитання: *«Чи можна використовувати Ollama без HTTP-запитів — напряму через CLI або безпосередньо в процесі?»*

**Коротка відповідь:** Навіть коли ви виконуєте команду в терміналі `ollama run model "промпт"`, сама Ollama під капотом **все одно здійснює локальний HTTP-запит**. 

Нижче наведено детальний технічний аналіз трьох можливих підходів і чому локальний Loopback HTTP (`HttpClient`) — це найкращий вибір для командного рядка.

---

### 1. Як насправді влаштована Ollama (Клієнт-Сервер)

Ollama побудована за модульною клієнт-серверною моделлю:
* **Сервер (`ollama serve`):** фоновий сервіс, який завантажує ваги моделі в пам'ять GPU (VRAM), керує чергою генерації та прослуховує локальний порт `127.0.0.1:11434`.
* **Клієнт (`ollama.exe`):** консольний бінарник. Команда `ollama run` **не виконує інференс автономно** — це CLI-обгортка, яка перетворює аргументи на HTTP POST-запит до `http://127.0.0.1:11434/api/generate`. Якщо фоновий демон ще не запущено, клієнт автоматично запускає `ollama serve` у прихованому фоновому процесі.

---

### 2. Порівняння трьох способів взаємодії

| Підхід | Механізм взаємодії | Затримка (Latency) | Використання VRAM | Гнучкість параметрів | Надійність та стабільність |
| :--- | :--- | :---: | :---: | :---: | :---: |
| **1. Локальний HTTP (`HttpClient`)** *(Обрано в TerminalAI)* | Прямий сокет до `127.0.0.1:11434` | **< 1 мс** на передачу (миттєво) | **Спільний пул** на всі вкладки термінала | **100%**: `temperature: 0.0`, `num_ctx`, `keep_alive` | **Максимальна**: ізольований сервіс, чистий JSON |
| **2. Виклик CLI (`& ollama run`)** | Створення нового дочірнього процесу `ollama.exe` | **+200–400 мс** на запуск процесу та runtime | Спільний пул (все одно йде через порт 11434) | **Обмежена**: важко міняти системний промпт на льоту | Вимагає парсингу ANSI-анімацій та спінерів зі stdout |
| **3. Без сервера (In-Process / `llama-cli`)** | Виклик `llama-cli.exe` або DLL напряму з диска | **+4–10 секунд** на КОЖЕН запит (читання 5 GB з SSD) | **Дублювання**: кожна вкладка займає свої 5 GB VRAM | Базова | Збій нативної C++ бібліотеки аварійно завершує PowerShell |

---

### 3. Чому прямий локальний HTTP (`HttpClient`) — найкраще інженерне рішення:

1. **Це не Інтернет-трафік (Zero Network Overhead):**
   - Запити на `127.0.0.1` (loopback) опрацьовуються виключно ядром Windows через внутрішній мережевий стек у пам'яті.
   - Вони **не використовують фізичну мережеву карту**, не залежать від підключення до мережі (Wi-Fi/Ethernet) і ніколи не покидають ваш комп'ютер.
   - Пропускна здатність локального сокета сягає кількох гігабайтів на секунду із затримкою менше 0.1 мілісекунди.

2. **Спільний VRAM-кеш між усіма вкладками Windows Terminal:**
   - Ви можете відкрити 10 різних вкладок PowerShell у Windows Terminal — усі вони паралельно звертаються до **однієї вже прогрітої моделі** у відеопам'яті.
   - Відкриття або закриття нових вкладок не витрачає час на повторне завантаження гігабайтів вагів моделі.

3. **Абсолютний контроль параметрів інференсу:**
   - Для надійної генерації PowerShell-коду критично важливо передавати суворі параметри:
     - `temperature: 0.0` — усуває випадковість і виключає галюцинації командлетів;
     - `num_ctx: 1024` — фіксує оптимальне вікно контексту, не перевантажуючи пам'ять;
     - `keep_alive: "1h"` — тримає модель готовою до миттєвої генерації без затримок.
   - Через CLI-команду `ollama run` передавати такі структуровані JSON-налаштування на кожен виклик складно та ненадійно.

## 🔧 Діагностика та усунення несправностей

### 1. Помилка з'єднання з Ollama (`Timeout` або `Connection refused`):
- Переконайтеся, що Ollama запущена:
  ```powershell
  ollama list
  ```
- Якщо служба зупинена, запустіть її командою: `ollama serve`.

### 2. Замість літер з'являються знаки запитання `??????`:
- Переконайтеся, що в консолі увімкнено UTF-8 кодування:
  ```powershell
  [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
  $OutputEncoding = [System.Text.Encoding]::UTF8
  ```
  *(Інсталятор `Install-TerminalAi.ps1` прописує ці рядки у ваш `$PROFILE` автоматично)*.

### 3. Гаряча клавіша не реагує:
- Якщо ви змінили налаштування, оновіть сесію в поточному вікні:
  ```powershell
  Import-Module TerminalAI -Force
  ```
- Для 100% надійності використовуйте клавішу **`F2`** — вона не залежить від активної мови (українська/англійська) чи стану клавіш Shift/CapsLock.

### 4. Комплексний запуск тестів розширення:
Для перевірки всіх систем розширення запустіть вбудований тест:
```powershell
pwsh -ExecutionPolicy Bypass -File .\Test-TerminalAi.ps1
```

## 🗑️ Деінсталяція

Якщо ви бажаєте повністю видалити розширення та відновити попередні конфігурації:

```powershell
pwsh -ExecutionPolicy Bypass -File .\Uninstall-TerminalAi.ps1
```
Скрипт автоматично:
- Видалить файли модуля з `$env:PSModulePath`.
- Очистить блок завантаження з вашого `$PROFILE`.
- Видалить зареєстрований фрагмент розширення з Windows Terminal.
- Запропонує видалити збережену конфігурацію `~/.terminal-ai`.
